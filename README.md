# F1 賽評文風微調：QLoRA 與證明它有效的評估框架

用歷年撰寫的 F1 賽後分析貼文對開源小模型做 QLoRA 微調，訓練出「我的文風」的
繁中賽評生成器，並建立評估框架證明微調的實際效果。

重點在**微調 + 評估方法論**，不在產品化。這個專案要回答的是：
微調到底改變了什麼、怎麼證明它不是自我感覺良好、以及它在哪些方面反而變差了。

## 與 `F1_Race_Analysis` 的分工

兩個專案的產出看起來像（都是賽事事實進、繁中賽評出），但解的問題不同。

| | `F1_Race_Analysis` | 本專案 |
|---|---|---|
| 手段 | 商用 API（Gemini）+ prompt + 三重守門 | 微調本地小模型（Qwen3 4B QLoRA） |
| 要證明的事 | 讓 LLM 寫文案但**不准在數字上說謊** | 微調能不能學到**特定作者的文風**，以及怎麼證明 |
| 核心產出 | 可上線的產線式管線，冪等、可排程 | 訓練設定與**評估框架**，含失敗案例 |
| 文風來源 | prompt 裡的規則與模板 | 模型權重 |

一句話的差別：**前者是把不可靠的模型用工程手段圍住，後者是問「改變模型本身能得到什麼」。**
兩者的評估標準也不同，前者看的是守門攔下多少錯誤，後者看的是三個系統的盲測與代理指標對照。

### 為什麼叫 Adaptation 不叫 Transfer

NLP 的 text style transfer 是**文字進、文字出**，改風格但保留內容，有明確的來源風格。
本專案是**結構化事實進、散文出**，沒有來源風格可轉，
屬於 style-conditioned generation。`Adaptation` 指的是把模型調適到目標風格，
那正是 LoRA 做的事，構詞沿用標準術語 domain adaptation。

## 基底模型：Qwen3 4B

三個候選都做得到，選 Qwen3 是為了省掉解釋成本與流程摩擦。
授權資訊為 2026-09-10 查 Hugging Face API 所得，不是憑印象：

| 模型 | 授權 | gated | 說明 |
|---|---|---|---|
| **`Qwen/Qwen3-4B`** | **apache-2.0** | **False** | 最乾淨。作品集展示與轉散布都無條件 |
| `google/gemma-3-4b-it` | `gemma`（自家條款） | manual | 可用，但要一併傳遞條款，且需在網頁先接受 |
| `meta-llama/Llama-3.2-3B-Instruct` | `llama3.2`（社群授權） | manual | 可用，需標註 Built with Llama，且需先接受 |

`gated=False` 是實際差別而不只是法律差別：**別人 clone 這份 Colab 就能直接跑**，
不必先去網頁接受條款、也不用設 HF token。作品集要能被打開才有意義。

繁中生成能力在計畫階段還要各做小測再定案，但若三者接近，Qwen3 勝出。

## 評估框架

驗收標準要求盲測人工評分，但那個設計有兩個先天弱點：
3 到 5 場 × 3 系統 = 9 到 15 篇，**樣本太小**；而且評分者是作者本人，
認得自己的句法習慣，**盲測不夠盲**。

所以人工 rubric 保留，但不讓它單獨承重。三個客觀指標與它並列：

| 指標 | 算法 | 用途 |
|---|---|---|
| `hallucination_rate` | 生成文的數字集合減去輸入事實的數字集合 | 事實正確性的硬規則。沿用 `F1_Race_Analysis` 的零容忍捏造原則 |
| `simplified_ratio` | 逐字簡轉繁，字形有變的算簡體 | 基底模型會漂到簡體，Qwen 尤其明顯。微調後必須接近 0 |
| `style_distance` | 功能詞分布的 Jensen-Shannon 距離 | 文風相似度的客觀代理。越小越接近參考文本 |

```python
from evaluation import evaluate
evaluate(input_facts, generated_text, reference_style)
# {'hallucination_rate': 0.0, 'invented_numbers': [],
#  'simplified_ratio': 0.0, 'style_distance': 0.0431, 'char_count': 128}
```

### 為什麼是功能詞而不是內容詞

文風的指紋主要落在「的了在是就而但卻」這類高頻功能詞的使用比例上，
內容詞則由輸入事實決定。拿功能詞當代理，量到的才是文風而不是題材。

### 一個踩過的坑

`simplified_ratio` 第一版是手打的「簡體專用字清單」，
結果被繁簡同形字污染（`圈`、`胎`、`乎` 在兩邊都是同一個字），
純繁體句子被誤判有 6.7% 簡體。測試抓到後改用 `zhconv` 逐字轉換判定。
**凡是能靠既有對照表判定的事，就不要手打清單。**

## 預期結果（先寫下來，實測後回填）

這一段刻意寫在實驗之前，避免事後把任何結果都說成「符合預期」。

| 系統 | 預期文風分數 | 預期事實正確性 | 預期可讀性 |
|---|---|---|---|
| 微調後 Qwen3 4B | **最高** | 中 | 中 |
| 未微調 Qwen3 4B | 最低 | 中 | 中低 |
| Gemini 純 prompt | 中 | **最高** | **最高** |

**預期 Gemini 會在事實正確性與可讀性上贏，微調版只在文風上贏。**
這是有價值的發現而不是失敗：它劃出了小模型微調的實際適用邊界，
也回答了「為什麼不直接用 API」這個一定會被問到的問題。

若實測結果是微調版連文風都沒贏，那就是資料量或訓練設定的問題，
報告要照實寫並分析原因，不改指標去遷就結論。
